# AI接続マニュアル — エディタから AI に編集を頼めるようにする

このエディタは、画面右の **AI タブ**から Claude Code / Codex CLI に日本語で編集を頼めます。
接続に必要な設定は**すべて自動**です。手動でコマンドを打つ必要はありません。

所要時間: **約1分**（Claude Code の導入が要る初回だけ数分）

---

## 1. 使い方（推奨・これだけで完結）

1. 動画を開いて、右ドックの **AI タブ**を開く。
   - Claude Code がまだパソコンに入っていなければ、「**AI と接続する（Claude Code を導入）**」ボタンが出るので押す（初回のみ・数分。`sudo` 不要・システムを汚しません）。
   - すでに入っていれば、ボタンを押さなくても自動で接続が始まる。
2. 画面内にターミナルが表示され「claude に接続しています…」のあと本物の Claude が起動する。**初回だけ**、通常の `claude` 起動時と同じログイン画面が出るので、いつも通りログインする（2回目以降はログイン不要）。
以上です。あとは**このターミナルに日本語でそのまま話しかける**だけです（例:「このテロップを赤にして」）。
Claude がプロジェクトのファイルを直接編集し、結果は画面に自動で反映されます。

> ターミナルの下に出る「**待機を開始（編集指示を受け付ける）**」ボタンは、編集指示の受け箱
>（自作スキルや外部ツールからの指示連携）を見張るモードに入るためのものです。ターミナルに
> 直接頼むだけなら押さなくてかまいません。

![エディタの AI タブ。動画を見ながら指示を打つと Claude Code が編集する](images/mcp-ai-tab.png)

しくみはシンプルです。編集内容はすべてテキストファイル（`telopData.ts` `cutData.ts` など）なので、
AI はそのファイルを直接読み書きし、エディタが変更を検知して画面に反映します:

```
AI タブのターミナル（あなたが話しかける）
        ↓ Claude がプロジェクトのファイルを直接編集
エディタが変更を検知して、画面に結果が反映される
```

### できることの例

- 「このテロップを赤にして」「文字をもっと大きく」
- 「『ゆる素振り』というドリル名を左上にずっと出して」
- 「0:30 あたりのテロップの誤字を直して」

編集が終わると、ターミナルに「テロップを赤にしました」のような返事が返ってきます。

## 2. Claude と Codex を切り替える（両方パソコンに入っている場合）

パソコンに **Claude Code と Codex の両方**が入っていれば、ターミナルの上に切替ボタン
（Claude / Codex）が出ます。**Claude だけが入っている場合はこのボタンは出ず、画面はこれまでと
何も変わりません。**

切替ボタンを押すと確認が出ます（実行中の編集は中断され、会話の内容も残りません）。OK すると
選んだ方のツールが新しく起動します。

「**待機を開始（編集指示を受け付ける）**」ボタンを押したときに自動入力される文言は、使っている
ツールによって違います:

- **Claude を選んでいる場合**: バックグラウンドの subagent に委譲して複数の動画を並列処理する文言。
- **Codex を選んでいる場合**: 指示を1件ずつ自分で片付けてから次を取りに戻る文言（直列処理。
  Codex は Claude のようにバックグラウンドへ委譲する運用を前提にできないため）:

  ```
  sme-editor の get_next_instruction を呼んで編集指示を待つ。指示が返ったら projectDir 配下のファイルを編集して実現し、作業中は .sme/status.json の activity を書く。完了したら report_instruction_status を done（失敗なら failed）で一言返答し、すぐ次の get_next_instruction を呼びに戻る。empty が返ったら再度呼んで待ち続ける。
  ```

**Codex を使うための前提**(任意・使わない場合は無視してよい): ターミナルで
`npm i -g @openai/codex` を実行して **版 0.145.0 以上**を導入し、ChatGPT にログイン済みであること。
Codex は自動導入ボタンの対象外のため、使いたい場合は先にターミナルで導入しておく。ログイン状態は
このパソコンの Codex のものをそのまま引き継ぐため、埋め込みターミナルで改めてログインする必要は
ない。**初回だけ**、このフォルダを信頼するか確認する英語の画面が出るので、Enter を押せば進める
（2回目以降は出ない）。

## 3. お金の安全（必ず読む）

- **`ANTHROPIC_API_KEY` を環境変数にセットしない**こと。セットされていると、サブスク（定額）ではなく API 従量課金で動いてしまいます。
- **`claude -p`（ヘッドレスモード）では回さない**こと。これも従量課金側です。必ず普通の対話セッション＋`/loop` で。
- 待機中（指示が来ていない間）はトークンを消費しません。サーバ側で最大約2分ブロックして待つ設計です。
- **作業が終わったら待機（`/loop`）を止める**（Esc または `/loop` 停止）。付けっぱなしにしないこと。
- AI タブの埋め込みターミナルは、起動時に `ANTHROPIC_API_KEY` 等の従量課金系の環境変数を自動で外します。外された場合は AI タブに「課金保護のため ◯◯ を外して起動しました」と出ます（意図的に使いたい場合のみ `SME_ALLOW_API_KEY=1` で無効化）。

## 4. つまずいた時の Q&A

**Q. 待機モードで送った指示が、いつまでも処理されない**

A. まず待機役の Claude（AI タブのターミナル、または別ターミナル）で `/loop` が回っているか確認してください。どうしても詰まった場合は、エディタを再起動すると「処理中」だった指示は中断扱いで解放され、次の指示が流れるようになります。

**Q. エディタを再起動したら指示はどうなる？**

A. 未処理（受付済み）の指示はファイルに保存されているため、再起動後も残ります。再起動時に「処理中」だった指示は結果が確認できないため中断扱いになります — 動画の状態を確認し、必要な場合のみもう一度指示してください。指示の控えは**プロジェクト置き場（`HARNESS_PROJECT_ROOT`）直下**の `.sme-inbox.json` に全動画共通で保存されます（置き場を git 管理している場合は ignore 推奨）。

**Q. 同時にたくさん書き出したら警告が出た**

A. パソコンの性能（CPU コア数・メモリ）から見て重い処理が多すぎるときに確認ダイアログが出ます。「それでも実行」を選べばそのまま実行できますが、パソコン全体が極端に遅くなることがあります。

**Q. 接続エラーになる**

A. エディタが起動しているか（ブラウザで画面が開くか）を先に確認してください。埋め込みターミナルはエディタが実際に動いているポートへ自動で追随するため、ポートを変えていても問題なく動きます。

**Q. 編集結果が画面に出ない**

A. エディタは外部からのファイル変更を自動検知してバナーを出します。バナーが出たら「再読み込み」してください。

## 付録: 別ターミナル運用（上級者向け）

AI タブの埋め込みターミナルは「全体待機（1つの待機役がすべての動画を担当）」の自動版です。
**動画ごとに専属の Claude を分けたい**場合や、外部のターミナルアプリで自分好みに操作したい
場合だけ、以下の手動手順を使ってください。**普段の利用でこの付録は不要です。**

### ステップ1: エディタを起動する

いつも通りエディタを立ち上げます（ポート 2109 で待ち受けます）。

### ステップ2: エディタとの接続を登録する（**初回のみ・1回だけ**）

外部ターミナルの Claude Code からエディタの受け箱を見られるようにするため、
**このエディタのフォルダ（harness-editor）に移動してから**、次を貼り付けます:

```bash
claude mcp add --transport http sme-editor http://localhost:2109/mcp
```

> **重要**: このコマンドは「Claude を起動するフォルダ」で実行します。別のフォルダで登録すると、そのフォルダで起動した Claude からしか見えません。AI タブの埋め込みターミナルはこの登録を自動で行うため、この手順が要るのは別ターミナル運用だけです。

### ステップ3: Claude を「待機役」として常駐させる（**使うたび**）

待機役の使い方は 2 つから選べます。迷ったら A で始めてください。

#### A. 全体待機（推奨・並列）— 1 つの待機役が全部の動画を担当

同じフォルダで `claude` を起動し、次をそのまま貼り付けます:

```
/loop sme-editor の get_next_instruction を呼んで編集指示を待つ。指示が返ったら、その場では編集せずバックグラウンドの subagent に委譲して、すぐ次の get_next_instruction を呼びに戻る。subagent には「projectDir 配下を編集して実現し、作業中は .sme/status.json の activity を書き、完了したら report_instruction_status を done（失敗なら failed）で一言返答する」ことを指示する。empty が返ったら再度呼んで待ち続ける。
```

複数の動画から同時に指示を出しても並行で処理されます（同じ動画への指示は、編集がぶつからないよう自動で順番に処理されます）。

#### B. 動画専属 — 1 つの動画に 1 つの待機役

動画ごとにターミナルを分けて張り付かせたい場合はこちら。次のひな形の `<この動画のID>` を
**動画のフォルダ名**（プロジェクト一覧に出る名前）に置き換えて貼り付けます:

```
/loop sme-editor の get_next_instruction を projectId: "<この動画のID>" で呼んで編集指示を待つ。指示が返ったら projectDir 配下のファイルを編集して実現し、完了したら report_instruction_status を done / failed で一言返答する。empty が返ったら再度呼んで待ち続ける。
```

- 専属がいる動画の指示は、必ずその専属が担当します（A の全体待機は横取りしません）
- 専属がいない動画の指示は、A の全体待機がいれば処理します
- 専属を止めてしばらく（約3分）すると、未処理の指示は全体待機が自動で引き継ぎます

**Q. Claude が「sme-editor というツールが見つからない」と言う**（別ターミナル運用のみ）

A. 埋め込みターミナルでは起きません。別ターミナル運用の場合は、ステップ2の登録が、Claude を起動したフォルダと違う場所で行われています。`claude` を起動するフォルダで `claude mcp add ...` をやり直してください。登録済みか確認するには `claude mcp list`。エディタが 2109 以外のポートで動いている場合もつながりません。
